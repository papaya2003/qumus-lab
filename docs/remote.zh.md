# 远程使用：看相机、远程控制、一键更新

适用情况：人不在实验室，用 Mac 连 Princeton VPN 远程工作。

| 想做什么 | 怎么做 | 能不能控制仪器 |
| --- | --- | --- |
| 看三台相机和仪器读数 | Mac 浏览器打开“只读页面”（端口 8790，需要钥匙链接） | 不能，只能看 |
| 动仪器、开关、加热 | 用 Chrome 远程桌面登录实验室电脑，在那台电脑的浏览器里打开 http://127.0.0.1:8780/ | 能（和在实验室一样） |
| 更新代码并重启 | 在实验室电脑上运行 `scripts\update.bat`（可以让 Codex 运行） | 会先检查，仪器在用时拒绝 |

## 1. 只读页面（在 Mac 上看相机）

- 启动程序时（`scripts\start-lab.bat`），窗口里会打印一行 `view-only page ... http://<实验室电脑IP>:8790/?key=...`。
  同一个链接也存在 `%USERPROFILE%\qumus-lab\runs\real-lab\viewer-url.txt`。
- 在 Mac 上连好 VPN，浏览器打开这个链接。第一次打开后钥匙会存进浏览器，以后直接打开
  `http://<实验室电脑IP>:8790/` 就行，建议加书签。
- 页面上有三台相机的实时画面（大约每秒 2 张，不保存），还有每台仪器的读数、模块是否锁定、谁在控制。
- 这个页面**只能看**：它只接受“读取”请求，没有任何移动、开关、加热、停止或解锁的入口。
- 钥匙相当于密码，不要发给别人。想换一把钥匙：删除 `runs\real-lab\viewer-key.txt`，然后重启程序。
- 第一次启动时 Windows 防火墙可能弹窗询问，选“允许”。如果 Mac 上打不开，多半是学校网络或防火墙没有
  放行 8790 端口，这时可以先用远程桌面看调试网页上的相机画面。

## 2. 远程控制

- 用 Chrome 远程桌面登录实验室电脑，在实验室电脑上打开 http://127.0.0.1:8780/ 。
  调试网页现在也显示三台相机的画面（“Cameras”一栏，可以关掉）。
- 控制入口只开在实验室电脑本机上，网络上的其他电脑无法控制仪器。
- **安全提醒**：人不在实验室时，相机能让你看到情况，但没人能去按电源开关。会动的步骤（L2 jog、加热）
  最好在有人在实验室时做，至少先确认 STOP ALL 和 Ctrl+C 都能停。

## 3. 一键更新（`scripts\update.bat`）

依次做三件事：
1. 从 GitHub 拉取最新的 main（`git pull`）；
2. 跑自检（和 `check.bat` 一样）；
3. 如果程序正在运行，就按原来的模式（真实或模拟）重启它，新窗口里启动。

下面这些情况会**拒绝**，什么都不改：
- 有模块正在执行命令（有仪器在动）；
- 有模块被锁定（必须先有人检查后在实验室电脑上解锁，重启不能绕过锁定）；
- 加热台在加热；有开关开着；
- 有人在控制（调试网页勾着 Take control，或 agent 在用）。先取消勾选再更新。

另外：
- 当前不在 main 分支、或有改了没提交的文件时，拒绝拉取（Codex 在别的分支上开发时，先合并或切回 main）。
- 拉取失败或自检有 FAIL 时，不会重启，正在运行的程序保持不动。
- 如果 `pyproject.toml` 变了，会自动重新安装依赖。
- 程序没在运行时，只拉取和自检，然后提示用 `start-lab.bat` 启动。

选项：`scripts\update.bat --no-restart`（只拉取和自检），`scripts\update.bat --no-pull`（只重启）。

## 用自己的 Windows 用户时注意

`config\devices.yaml` 里 Dracal 温度计程序和显微镜相机 SDK 的路径在 `C:\Users\Qumus_PC\...` 下面。
如果你登录的是自己的 Windows 用户，可能没有权限读别人的用户文件夹。`check.bat` 的厂商软件那一行会报出来；
解决办法是请电脑管理员把这两个文件夹复制到公共位置（例如 `C:\Qumus-vendor\`），再改 `devices.yaml` 里的路径。
